# WWW collective-dependence programme

1. Pilot on four stored random-feature checkpoints; independent flips, prevalence-preserving exchanges
   and feasible signed-degree-preserving four-cycles. Validate the diagnostic on known sparse,
   distributed, redundant and saturated solvers; train one distributed regime.
2. Expand controlled mechanisms, replicate checkpoint seeds and add published-objective random inputs.
   Specify each expansion before computation. Keep the full outcome ledger and name every distribution.
3. Develop one computation-allocation application on independent development/validation queries; lock
   the policy before held-out testing. Test actual approximations and include all offline/online costs.
4. Revise the scientific centre of the manuscript only after the evidence supports a reusable contribution.
   Compare against existing range and explanation-fidelity methods; retain the current validated version
   as the baseline. The existing anonymous submission artifact is unchanged during this pilot.

A pilot can establish feasibility and a phenomenon worth studying. It cannot establish an 8/10 score,
priority, a causal model of real users, or robust cross-seed generality. Both small and large collective
effects will be reported; neither is a prescribed success outcome.
